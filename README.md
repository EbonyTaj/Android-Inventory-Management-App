# Android Inventory Management App

## CS 360: Mobile Architecture and Programming

### Project Overview

For this project, I developed an Android Inventory Management App using Java, SQLite, and Android Studio. The goal was to create an app that allows users to manage their inventory without having to keep track of everything manually. Users needed a way to log in, view inventory, add new items, update quantities, and delete items they no longer needed. The app was also designed to support optional SMS notifications when inventory levels get low.

### User Interface and Design

When designing the app, I wanted to keep things simple so users wouldn't have to spend time figuring out how to navigate it. I created a login screen and an inventory screen where users could manage their items. I focused on making buttons easy to understand, keeping the layout organized, and providing feedback when users completed an action.

Coming from a Product Owner background, I'm used to thinking about what users need before development begins. This project gave me the opportunity to take those requirements and turn them into an actual working interface. I think the design was successful because it focused on the main tasks users needed to complete without making the app unnecessarily complicated.

### Coding Approach

I approached development by working on one feature at a time instead of trying to build everything at once. I used Java to handle the app's functionality and SQLite to store user and inventory information. Breaking the work into smaller pieces made it easier to understand how everything connected and troubleshoot problems along the way.

I also learned how important it is to organize code and test features as they're developed. That's something I plan to continue doing in future projects because it makes problems easier to find and fix.

### Testing and Troubleshooting

I used the Android Studio emulator to test the app and check that its features worked as expected. For example, I tested the login process, inventory management functions, and input validation to make sure users couldn't submit incomplete or incorrect information.

Testing showed me that just because an app runs doesn't mean everything works correctly. Sometimes a feature looked fine on the screen, but I still needed to check how it behaved when someone actually used it. This helped me understand why testing is such an important part of development.

### Challenges and Problem-Solving

One challenge I worked through was making sure the app handled user input correctly. I needed to prevent users from entering invalid information while still making the app easy to use. This meant reviewing the input validation, adjusting how the app responded to user actions, and testing different scenarios.

I learned that solving problems in development often takes some trial and error. Instead of changing several things at once, I found it more helpful to focus on one issue, make an adjustment, and test again.

### My Biggest Success

I'm most proud of connecting the Inventory App to the SQLite database and getting the inventory features to work together. Before this course, I understood databases and application requirements more from a business and product perspective. Actually writing the code and seeing information saved and retrieved gave me a better understanding of how those systems work behind the scenes.

Overall, this project helped me connect my Product Owner experience with the technical skills I've been learning throughout my Computer Science program. It also gave me more confidence working with Android Studio, Java, and databases. I plan to keep improving the app and use what I've learned in future development projects.
